## Summary
Below is the original description of the vulnerability. Initially this was confirmed and supported with a written report of the researcher. After transfer of the CVE, Siemens investigated further. Siemens was unable to reproduce the vulnerability following the documented steps. The researchers did not provide further evidence to support the claim, so DIVD CNA team accepted the withdrawal of CVE-2026-7891.
DIVD is still cooperating with Siemens and Mendix to find vulnerable configurations of Mendix, and send out notifications. 

WITHDRAWN: The VerySecureApp made by DIVD using Mendix Studio Pro 11.8.0 Beta allows unintended data exposure due to authorization misconfiguration. The VerySecureApp allows anonymous users of the MyFirstModule with the anonymous user role to gain access to all stored records, even though no access rights are explicitly configured on that role. Anonymous users are required to make a Mendix Entity available publicly. All versions of Mendix Studio Pro up to 11.8.0 Beta silently make an Anonymous user role follow user inheritance rules, without mentioning this explicitly in the documentation.

## What you can do
WITHDRAWN: Don't use the DIVD VerySecureApp, and consider whether you have similar Mendix created apps with Anonymous user roles without explicit permissions definitions.

## What we are doing
DIVD is actively scanning and alerting similar Mendix created apps, and verifying data leaks before alerting. If you run a similar Mendix app, please have a look at our [instructions](https://www.divd.nl/mendix.html).
